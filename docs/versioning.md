# Deskmark 版本号

Deskmark 用自己的版本号，不接着 MarkText 的 0.20.0 往下数。分叉基线是上游 tag v0.20.0。这个事实写在发布说明里，不写进版本号。

版本号是三段：大.小.修。

- 大版本：开发计划里的一个阶段达到出口，并且这次提交让产品多了一种能力；或者笔记格式、插件 API 不再兼容。小版本和修订号归零。阶段 0 只做分叉、探针和边界，不改用户的 Markdown，所以阶段 0 结束仍然停在 0.x。从阶段 1 起，达成阶段出口的那一次提交升大版本。阶段 1 是任务模型，版本为 1.0.0。其后每个阶段出口各升一次大版本。
- 小版本：一个向后兼容的功能。一个功能一次提交。修订号归零。
- 修订号：不增加功能的修正。大版本和小版本不动。

下面这些不算一次功能，不单独升版本：只改措辞、注释或格式；同一次功能里附带的测试和发布说明；失败后立刻补上的同类回归。

应用版本以 packages/desktop/package.json 的 version 为准。根目录 package.json 的 version 与它保持一致。@muyajs/core 和其他上游包的版本不动，那些是引擎版本，不是桌笺的版本。

每次升版本写一份说明：docs/releases/release-version大.小.修.md。说明里写这次是大版本还是小版本、做了什么、没做什么、基于哪一次上游。

提交信息的第一行说明功能。正文写上版本号。不要把几个功能挤进同一次提交。
